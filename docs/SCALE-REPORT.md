## Checks

| Area | What | Result | Limit | Verdict | Fix |
|---|---|---|---|---|---|
| Database, whole site | Peak writes per second (exam week) | 13,047 at 16:36 UTC | No fixed limit; traffic must grow gradually | **Pass** | Grow by school, not all at once; warn Google before a very large launch |
| Database, whole site | Peak reads per second | 104,608 at 16:00 UTC | No fixed limit | **Pass** |  |
| Database, one record | Most writes to one record per second | 1 or less: every student writes only their own records | About 1 a second | **Pass** | Keep it so: never a shared counter (scale rule 2) |
| Exam rush | Biggest exam (5,000 seats): writes per second into its attempts | 200 at peak | 500 a second when a timestamp is indexed | **Pass** | Stop indexing beatAt, startedAt and submittedAt (free); spread the countdown reload over 0 to 5 seconds |
| Exam rush | Same exam if everyone pressed Start in one second | 5,000 | 500 a second | **Fail** | The same two fixes; then the limit no longer applies |
| Exam rush | Security-rule lookups when starting an exam | About 6 | 10 per request | **Pass** | Every new exam rule must keep the total under 10 |
| Records too big | Class roster (one record) for 5,000 students | 547 KB; full at 9,361 students | 1 MiB per record | **Watch** | One record per student (rosters/{class}/people/{email}) before classes over 5,000 |
| Big reads | Professor dashboard, 5,000-student class | 150,000 records each time it opens | Works, but slow and costly above ~10,000 | **Fail** | A summary record per class and section, updated by the server; the dashboard reads a handful |
| Big reads | Admin pages: every user, every class, every sign-in | 20,000,000 users and 1,666,667 classes read on one page | A browser handles a few thousand | **Fail** | Pages of 50, search, and counts from the database (count queries) |
| Big reads | Admin sign-in loads every class | 1,666,667 classes | Same | **Fail** | Load the admin's list only when the page needs it, a page at a time |
| Sign-in | New accounts from one campus network (a 300-seat first lecture) | 300 in a few minutes | 100 an hour per address | **Fail** | Ask Firebase to raise it two weeks before each school starts, or sign in through the school (SSO); confirm whether Google sign-in counts |
| Sign-in | Sign-in renewals per minute at the busiest time | About 22,685 | 18,000 a minute per project (meaning to confirm with Firebase) | **Watch** | Confirm with Firebase what counts; Identity Platform raises limits on request |
| Hosting | GitHub Pages for a paid product | 30,247 app opens a minute | 100 GB a month; no commercial software (SaaS) | **Fail** | Move to Cloudflare Pages or Workers static assets before the first school pays (same files, free plan, no bandwidth limit) |
| AI | AI requests per minute at the busiest time | 25,052 | Each AI company sets a limit per customer | **Watch** | Arrange higher limits before each large school; bring-your-own AI spreads the load |

## Assumptions

5 classes a student, 60 students in an average class, biggest class 5,000. 50% open Cramming on the day, 12% sit a 50-minute exam (exam week). Time zones: Eastern 47%, Central 29%, Mountain 7%, Pacific 17%. Reads and writes per action follow the code as of November 2026; change them at the top of scripts/scale.mjs when the code changes.
